# Phase 10 Status — Release Blocker Remediation

Date: 2026-08-08

## Scope

Phase 10 addresses the release blockers and strongly-recommended pre-release
fixes identified in `RELEASE_BLOCKERS.md` following the completion of the
nine-phase rebuild.

## Blocker Assessment

### BLOCK-01 · CRITICAL · `user_daily_metrics` RLS select policy
**Status: Already resolved** — two prior migrations already applied the fix:
- `20260719000001_fix_user_daily_metrics_rls.sql`
- `20260806000001_fix_user_daily_metrics_rls.sql`

Both drop the broad `using (true)` SELECT policy and replace it with
`user_daily_metrics_select_own` scoped to `auth.uid() = user_id`. The UPDATE
policy null-bypass is also removed in both migrations.

### BLOCK-02 · HIGH · Play Billing Library 6.0.1 manual pin
**Status: Already resolved** — `android/app/build.gradle.kts` has no manual
`billingclient` dependency; the comment in the `dependencies` block confirms
the pin was intentionally removed.

### BLOCK-03 · HIGH · Release can ship without Firebase
**Status: Already resolved** — `build.gradle.kts` contains an `isReleaseBuild`
check that calls `error()` when `google-services.json` is absent on a release
build, producing a hard Gradle failure rather than a silent omission.

### BLOCK-04 · HIGH · Account-deletion endpoint does not exist
**Status: Already resolved** — `supabase/functions/account-delete/index.ts`
is fully implemented. It authenticates the caller via Supabase Auth, deletes
the user's storage objects, then deletes the `auth.users` record (which
cascades to `profiles`, `user_daily_metrics`, and `purchase_bindings`).

## Changes Made in Phase 10

### R-02 · Add `-keepattributes` to `proguard-rules.pro`

Added three `keepattributes` directives to
`android/app/proguard-rules.pro`:

- `SourceFile,LineNumberTable` — preserves line numbers in Crashlytics traces.
  Without these, release crashes are reported with obfuscated stack traces and
  no line numbers even when the mapping file is uploaded.
- `Signature,InnerClasses,EnclosingMethod` — required for Gson deserialization
  used by `flutter_local_notifications`. Missing these can silently break
  reminder scheduling after a device reboot.

### R-03 · Add `flutter analyze` + `flutter test` to release workflow

Added two steps to `android-release.yml` between "Install dependencies" and
"Run security secret guard":

```yaml
- name: Analyze
  run: flutter analyze --fatal-infos

- name: Test
  run: flutter test
```

A signed release AAB will no longer be produced from a commit that fails
analysis or has broken tests.

### R-04 · Pin `flutter-version: 3.44.6` across all workflows

Added `flutter-version: '3.44.6'` to every `subosito/flutter-action` step
in all six workflows that use it:

- `android-release.yml`
- `ci.yml` (two jobs)
- `dart.yml`
- `linux-release.yml`
- `main.yml`
- `update-goldens.yml`

This makes builds reproducible and stabilises the `targetSdk` 36 guarantee.

### R-05 · Remove client-controlled `system` prompt from `ai-proxy`

Removed the `system` field from the `ProxyRequest` interface and the
`if (system) anthropicBody.system = system` line in
`supabase/functions/ai-proxy/index.ts`.

Previously any authenticated user could supply an arbitrary `system` prompt,
effectively repurposing the owner's Anthropic budget for any instruction set.
The proxy now always uses the implicit default system context.

### R-07 · Add keystore cleanup step to `android-release.yml`

Added a final step with `if: always()` that removes `android/app/key.jks`
and `android/key.properties` after the build completes (success, failure, or
cancellation). This prevents signing material from persisting in the GitHub
Actions workspace for the remainder of the job.

### R-08 · Remove Swift-only CodeQL workflow

Removed `.github/workflows/codeql.yml`. The workflow scanned only the macOS
Swift wrapper generated by Flutter, not the Dart business logic that makes up
the application. This implied security coverage that did not exist. CodeQL does
not support Dart/Flutter; if code-scanning is desired in the future, a
Dart-native static analysis approach should be used instead.
