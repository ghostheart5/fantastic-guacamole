CHRONOSPARK AI / MODEL BUILDER AUDIT
Date: 2026-07-31
Scope: AI-powered product behavior, model inputs, prompts, reasoning context, generated outputs, predictions, summaries, classifications, and decision support.
Mode: Audit only. No code changes.

This audit covers AI surfaces in the mobile app only. It does not modify AI logic, routing, providers, billing, auth, Supabase, or secrets.

============================================================
SECTION 1: EXECUTIVE AI SUMMARY
============================================================

Current AI identity:
- ChronoSpark has a real AI layer, but it is mostly a local-first, heuristics-driven decision-support system with an optional proxy path rather than a fully external LLM app.
- The strongest live AI surfaces are Smart Coach, SI Console, the AI controller / agent orchestrator layer, and the trajectory / future-forecast stack.
- AI is used for coaching, summaries, recommendations, forecast narration, intent classification, and structured status reporting.

What currently exists:
- Smart Coach is active and user-facing in [lib/features/home/ui/smart_coach_screen.dart](lib/features/home/ui/smart_coach_screen.dart) with prompt construction in [lib/state/controllers/coach_query_controller.dart](lib/state/controllers/coach_query_controller.dart).
- SI Console is active and user-facing in [lib/features/si_console/ui/si_console_screen.dart](lib/features/si_console/ui/si_console_screen.dart) with the main aggregation in [lib/state/providers/si_pipeline_provider.dart](lib/state/providers/si_pipeline_provider.dart).
- Future Vector exists in practice as the trajectory / forecast stack, with the main screen at [lib/features/trajectory_engine/ui/trajectory_engine_screen.dart](lib/features/trajectory_engine/ui/trajectory_engine_screen.dart) and providers such as [lib/state/providers/trajectory_provider.dart](lib/state/providers/trajectory_provider.dart), [lib/state/providers/future_timeline_provider.dart](lib/state/providers/future_timeline_provider.dart), and [lib/state/providers/future_decision_engine_provider.dart](lib/state/providers/future_decision_engine_provider.dart).
- Ascension is not a standalone AI feature folder, but progression / momentum / streak logic is active through profile and progression providers.
- Nexus / Home exposes a lightweight system summary and initial guidance in [lib/features/nexus/ui/nexus_screen.dart](lib/features/nexus/ui/nexus_screen.dart).
- The AI controller and agent layer are active in [lib/state/controllers/ai_controller.dart](lib/state/controllers/ai_controller.dart) and [lib/data/services/ai/orchestration/agent_orchestrator.dart](lib/data/services/ai/orchestration/agent_orchestrator.dart).

What appears planned or partially wired:
- Smart Planner exists as a concept and tutorial surface, but not as a dedicated standalone folder or full model-builder surface. Planning is mostly implemented as deterministic weekly/daily providers and SI Console commands.
- Future Vector is partially wired as forecast / trajectory / simulation / identity drift providers, but not as an external model system.
- Ascension is primarily a rule-based progression stack rather than a dedicated AI assistant.
- The AI agent layer has multiple named agents, but most are local heuristics, deterministic summaries, or SIAIService wrappers rather than direct external model calls.

What data AI currently uses:
- Tasks, goals, memory notes, timeline events, progression state, profile state, learning state, execution signals, trajectory / momentum state, core values, soul map, emotional state, and local conversation history.
- Smart Coach also uses notes and follow-up text, then writes mirrored memory and timeline emotion check-ins.
- SI Console uses aggregated app state plus autonomous planner output.
- Future Vector uses task counts, completion and execution signals, energy, learning metrics, session score, identity drift, and forecast heuristics.

What data AI should use more consistently:
- Explicit completion history as a first-class signal.
- Schedule density and actual planned items as a first-class forecasting input.
- Routine / habit activity as a clear AI input.
- Subscription / access context only where it changes behavior or explainability.
- More explicit app-state context for the AI surfaces that currently infer from summaries.

Timing:
- AI does not appear mandatory during onboarding.
- The onboarding flow is a setup gate only in [lib/features/onboarding/ui/onboarding_screen.dart](lib/features/onboarding/ui/onboarding_screen.dart).
- Tutorial content introduces Smart Planner and Forecast later, after Home Overview, which is directionally correct.
- The risk is not that AI appears too early in onboarding; the larger issue is that some AI surfaces are available before the app has enough real user activity to be maximally grounded.

Overlap:
- Smart Coach, SI Console, and Future Forecast overlap in “give me the next move” style guidance, but they still have different intended jobs.
- Some planning and forecast logic is duplicated across Smart Planner labels, SI Console commands, trajectory providers, and coaching fallback text.
- The overlap is not a correctness bug yet, but it does blur the mental model.

Actionability:
- Outputs are often actionable, but not consistently action-producing.
- The best outputs point to a next step, but there is still no consistent create-from-AI loop that turns AI advice directly into a task, routine, goal, or scheduled timeline item.

Verdict:
REWIRE
- Keep the grounded local-first AI backbone.
- Rewire the context pipeline so completion, schedule, and progression become the canonical AI inputs.
- Simplify overlap between Smart Coach, SI Console, and forecast surfaces.

- Energy and emotion are included explicitly.
- Goals, memories, timeline summaries, tasks, profile, progress, insights, logs, notifications, plan preview, core values, soul map, and current SI state are included in the broader coach context.

- Yes, through AIController, coach context, and task counts / task previews.

Whether routines are included:
- Not explicitly as a first-class AI input in the main coach context.
- Routines exist in Creator and planning flows, but they are not clearly surfaced as a dedicated AI input in the coach prompt path.

Whether goals are included:
- Yes.

Whether notes are included:
- Yes. Notes are the main coaching input, and they are also mirrored into local memory storage when saved.

Whether schedule / timeline is included:
- Yes, but mostly through timeline summaries and plan preview rather than raw schedule model detail.

Whether completion history is included:
- Partially. Completion affects progression, momentum, and timeline signals, but there is no single canonical completion-history stream passed as a distinct AI context object.

Whether profile context is included:
- Yes.

Whether subscription / access context affects behavior:
- Yes, indirectly. AIController applies credit consumption and paywall behavior, and the chat proxy only sends an auth token when available.
- The prompt itself does not appear to include rich subscription detail, but runtime AI availability is affected by credits and paywall state.

Whether response is stored:
- Yes.
- Smart Coach persists conversation turns and mirrored memory / reflection notes.
- AIController persists agent trace / response trace / AI state and can append neural dump entries.

Whether response creates app actions:
- Not directly in the sense of creating a task or scheduled item.
- It does create side effects: mirrored memory, timeline emotion check-in, XP increase, and stored conversation turns.

Whether response can route back to Creator or Timeline:
- Not as a direct create action.
- It can encourage next steps that should be acted on in Creator or Timeline, and the app already has navigation to those surfaces elsewhere.

Classification:
- useful: Yes.
- disconnected: No.
- too generic: Sometimes, if context is sparse or the proxy falls back.
- partially grounded: Yes.
- well-grounded: Mostly yes for active users with real data.
- unknown: The external proxy path remains runtime-dependent.

Smart Planner / Smart Coach readiness score: 68 / 100
- Strong context and persistence.
- Weakness: no canonical create-from-AI action and no explicit routine / schedule-first model.

SECTION 14: AI FEATURE OVERLAP AUDIT
============================================================

1) Smart Coach vs SI Console
- Overlap: both surface advice and next-step guidance.
- Distinct jobs: Smart Coach is personal / emotional / productivity coaching; SI Console is whole-app intelligence and diagnostics.

- Overlap: both generate next-step guidance and future-facing direction.

- Overlap: both explain pressure, momentum, trajectory, and likely outcomes.

- Overlap: all talk about level, XP, streak, and momentum.
- Distinct jobs: Ascension should remain the interpretation layer, while profile / progression remain the state layer.
- Recommendation: keep rule-based progression, then let AI interpret it.

5) Nexus / Home vs Smart Coach
- Overlap: both deliver a daily summary and a suggested next move.
- Distinct jobs: Nexus is a dashboard; Smart Coach is a conversational support surface.
- Recommendation: keep both, but ensure the dashboard summary stays short and the coach remains the interactive depth layer.

Overall overlap verdict:
- The app has useful redundancy, but some surfaces are narrating the same thing in slightly different words.
- The safest path is to sequence these surfaces rather than merge their jobs blindly.
