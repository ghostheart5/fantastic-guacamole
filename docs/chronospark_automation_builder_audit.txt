SECTION 1
EXECUTIVE AUTOMATION SUMMARY
============================================================

What automations exist:
- Creator save fan-out for tasks/goals through action providers with side effects:
  - task create -> timeline connect/mirror, log mirror, metrics, event bus, coach refresh
  - goal create/update/complete -> reminder sync, timeline connect/mirror, XP, event bus
  - Evidence: lib/state/providers/creator_provider.dart, lib/state/providers/task_provider.dart, lib/state/providers/goals_provider.dart
- Timeline execution automations:
  - Complete / Not Completed / Skip / Reschedule actions invoke task automations
  - Evidence: lib/features/timeline/ui/timeline_screen.dart, lib/state/providers/task_provider.dart
- Event-driven invalidation automation:
  - Domain event bus triggers provider invalidation across tasks/goals/logs/timeline/notifications/progression
  - Evidence: lib/state/providers/event_bus_provider.dart, lib/state/core/state_bootstrap.dart
- Notification automation exists for local reminders:
  - goal reminders, habit reminder, daily planning reminder, reflection reminder
  - Evidence: lib/state/services/reminder_orchestrator_service.dart, lib/state/services/reflection_reminder_service.dart, lib/system/notifications/notification_scheduler.dart
- Background scheduler automations:
  - offline sync replay every 15m, AI precompute every 20m
  - periodic data hygiene cleanup
  - Evidence: lib/system/system_scheduler.dart, lib/state/services/data_hygiene_scheduler.dart, lib/app/navigation_shell.dart
- Supabase automation exists in specific bounded areas:
  - health checks + realtime stream for user_daily_metrics
  - cloud backup sync and offline queue replay
  - FCM token -> Supabase auth metadata bridge
  - monetization table reads and RPC credit consume
  - Evidence: lib/state/providers/supabase_backend_provider.dart, lib/state/providers/sync_provider.dart, lib/data/services/sync_service.dart, lib/data/repositories/firebase_supabase_bridge_repository.dart, lib/features/monetization/data/monetization_remote_data_source.dart

What automations are missing:
- No explicit dedicated Note pipeline (notes are saved as task kind note, no note-specific downstream handling).
- No explicit routine-instance engine (daily routine recurrence relies on task recurrence semantics, not a dedicated daily instantiation job).
- No centralized completion event orchestrator that atomically guarantees full chain propagation across Timeline -> Ascension -> Future Vector -> Smart Planner -> SI Console.
- No robust global retry/backoff policy for all Supabase read paths (monetization reads mostly direct).
- No explicit conflict-resolution automation beyond sync merge logic in backup sync.

Which automations are most valuable:
- Task and goal save fan-out in providers.
- Timeline action automations (complete/skip/not completed/reschedule).
- Event bus invalidation bootstrap.
- Offline queue replay + periodic scheduler.

Which automations create confusion:
- Smart Planner naming vs actual screen/controller split (Nexus + SmartCoach + SI pipeline sources).
- Mission step naming mismatch (e.g., reportCreatorOpened completes configure step in mission state).
- Ascension concept spans profile XP/progression/momentum rather than single authoritative pipeline.

Which automations are duplicated:
- Multiple independent coach refresh triggers after many mutations (task/goals/logs/notifications/timeline each can trigger decision refresh).
- Timeline and logs both mirror lifecycle signals in separate fan-outs.
- Notifications can be scheduled through multiple service paths (orchestrator + reflection service + notification provider).

Verdict:
- KEEP: Core task/goal/timeline fan-out + event bus invalidation + scheduler/replay foundation.
- REDESIGN: Cross-system completion orchestration and Smart Planner/Future Vector feed contracts.
- MERGE: Duplicate decision refresh and mirror-write pathways.
- REMOVE: Dead/legacy-like automation ambiguity from non-authoritative alternate pathways (after migration verification).
- UNKNOWN: Some advanced AI/trajectory/autonomous modules that compute from derived providers but are not fully event-contract-based.

TIMELINE AUTOMATION AUDIT
============================================================

Does Timeline auto-refresh after create?
- Yes, via timelineProvider invalidations and connectTask/connectGoal calls.

Does Timeline auto-update completion state?
- Yes for task actions from Timeline and task completion side effects (mirrored completion event).

Does Timeline auto-update overdue status?
- Partial: overdue is derived by event properties and filtering; no dedicated overdue recalculation scheduler per entity class beyond timeline query rebuild.

Does Timeline auto-update routines?
- Partial: routines flow through task-like entities; no dedicated routine instance engine that continuously seeds timeline entries.

Does Timeline auto-update indicators?
- Yes: health/risk/upcoming/milestones/recommendations are provider-derived and recomputed.

Does Timeline auto-update progression?
- Partial: timeline actions can trigger XP via task/goal fan-outs; timeline itself does not own progression state updates directly.

Missing automation:
- Explicit routine instantiation and overdue rollover logic beyond manual action path.
- Dedicated note timeline semantics.
- Unified “completion propagated” confirmation event across all downstream systems.

-> status saved
-> Timeline updated
-> Ascension updated

Where the chain breaks:
- No singular completion orchestrator with ack that all downstreams consumed the completion signal.
- SI Console receives direct stream for goals, but not equivalent direct stream UX for task lifecycle updates.
- Future Vector/Smart Planner updates are mostly derived-provider recomputation rather than explicit event contract per completion.

SECTION 13
EVENT CHAIN MAP
============================================================

Create Item:
- Trigger: Creator submit
- Provider: creatorActionsProvider -> taskActionsProvider/goalsProvider
- Storage: task/goal repository write
- Supabase: indirect (backup/sync paths), not direct live create write in these providers
- Timeline: connectTask/connectGoal + mirrored events
- Ascension: XP via profile updates (task/goal fan-outs)
- Future Vector: indirect via execution/momentum/trajectory recompute
- Smart Planner: indirect via SI aggregation providers
- SI Console: indirect via provider pull; goal create has direct lifecycle event visibility potential
- Broken links: note/routine specialized semantics

Update Item:
- Trigger: updateCreatorEntry / goal update methods
- Provider: taskActionsProvider/goalsProvider
- Storage: update usecases
- Supabase: indirect through sync/backups
- Timeline: mirrored goal updates; task update has log + event bus but weaker dedicated timeline semantics
- Ascension: limited XP path on goal updates
- Future Vector / Smart Planner / SI Console: mostly indirect recompute
- Broken links: no unified update event contract across all intelligence consumers

Delete Item:
- Trigger: task/goal delete usecases in providers (where invoked)
- Provider: goals/task/routine pathways
- Storage: delete usecases
- Supabase: indirect
- Timeline: partial depending on usecase path; some removes rely on specific timeline delete flows
- Ascension/Future/Planner/Console: indirect via invalidation
- Broken links: deletion propagation consistency is uneven by domain/action path

Complete Item:
- Trigger: timeline action or task/goal completion methods
- Provider: taskActionsProvider.completeTask / goalsProvider.complete
- Storage: completion usecases
- Supabase: indirect
- Timeline: mirrored completion events
- Ascension: XP/streak updates
- Future Vector: execution/momentum/trajectory update path
- Smart Planner: SI provider recompute
- SI Console: partial push (goal events) + pull recompute
- Broken links: no explicit end-to-end completion ack chain

Skip Item:
- Trigger: timeline skip action
- Provider: taskActionsProvider.skipTask
- Storage: state mutation via usecases
- Timeline: mirrored skipped event
- Ascension: indirect via momentum/learning effects (not direct XP reward)
- Future/Planner/Console: via execution signals and provider recompute
- Broken links: limited explicit downstream event contracts

Reschedule Item:
- Trigger: timeline reschedule/not completed
- Provider: taskActionsProvider.delayTask
- Storage: task scheduledFor update
- Timeline: mirrored delayed/not-completed event
- Ascension/Future/Planner/Console: indirect through logs/execution/provider recompute
- Broken links: no unified SLA for delayed-item recovery automation

SECTION 18
IDEAL CHRONOSPARK AUTOMATION MODEL
============================================================

Ideal chain:
Create
-> Save
-> Timeline
-> Completion
-> Progress
-> Forecast
-> Coaching
-> Console

Step-by-step ideal automatic behavior:
1) Create
- User submits Task/Routine/Goal/Note from Creator.
- Input normalized into canonical lifecycle payload with type-specific metadata.

2) Save
- Single write succeeds and emits one canonical lifecycle event.
- Event has idempotency key + action source + correlation id.

3) Timeline
- Timeline receives canonical event and updates once.
- Overdue/upcoming/recommendation indices recompute deterministically.

4) Completion
- Completion action emits canonical completion event.
- Completion event updates logs, metrics, and status exactly once.

5) Progress
- Ascension/progression consumes completion event to update XP, streak, consistency contributions.

6) Forecast
- Future Vector consumes updated completion + deadline + deferral + consistency state.
- Forecast confidence and rationale are persisted for diagnostics.

7) Coaching
- Smart Planner consumes latest forecast + execution context to produce next action.

8) Console
- SI Console receives push summary of lifecycle transitions and can pull full context on demand.

No implementation performed in this audit.
