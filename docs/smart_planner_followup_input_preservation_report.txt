CHRONOSPARK SMART PLANNER FOLLOW-UP INPUT PRESERVATION FIX REPORT
Date: 2026-08-01

1. File changed
- lib/features/home/ui/smart_coach_screen.dart

2. Root cause
- In _sendFollowUp(), _followUpController.clear() was executed before the async follow-up request completed.
- If requestFollowUp() timed out or threw, the typed follow-up text had already been removed.

3. Old behavior
- User types follow-up.
- _sendFollowUp() reads trimmed text.
- Controller was immediately cleared.
- Request runs.
- On timeout/error, _followUpError is shown but typed input is already lost.

4. New behavior
- User types follow-up.
- _sendFollowUp() reads trimmed text into local final text.
- Request runs with _sendingFollowUp=true.
- Controller is cleared only after successful reply is received and applied.
- On timeout/error, typed input remains available for retry.

5. Whether controller is cleared only after success
- Yes.
- _followUpController.clear() was moved from pre-request path to success path (inside setState after reply).

6. Timeout behavior
- Preserved timeout duration and message.
- On TimeoutException:
  - _sendingFollowUp set false.
  - _followUpError set to: Follow-up timed out. Try a shorter prompt.
  - Follow-up input text is preserved (not cleared early).

7. Generic error behavior
- Preserved generic error handling.
- On catch:
  - _sendingFollowUp set false.
  - _followUpError set to: Follow-up could not be sent. Try again.
  - ErrorBoundary capture remains.
  - Follow-up input text is preserved (not cleared early).
