============================================================
1) CURRENT STATE MAP (STEP 1 RELEVANT)
============================================================
Observed authority split:
- Onboarding status flags/keys live in app providers.
- Startup/bootstrap reads persisted state and initializes runtime state.
- Onboarding screen sets progression/completion values.
- Mission completion hook in app root can also mark onboarding complete.

Risk in current split:
- Multiple write points can drift if key/version/write-order assumptions diverge.
- Inconsistent writes can cause redirect loops or first-session misroutes.

============================================================
2) TARGET STATE MAP (STEP 1)
============================================================
Canonical authority rule:
- app_providers owns key names, status enums, and authority semantics.
- bootstrap is the canonical startup reader/normalizer.
- onboarding screen is an approved writer through canonical helper path.
- app root mission-completion write remains allowed but must use same helper path semantics.

Required properties:
- Single completion meaning: complete == onboarding gate lifted.
- Single content-version ownership definition.
- Single default/fallback when persisted data is malformed.
- Deterministic bootstrap order for onboarding state only.
