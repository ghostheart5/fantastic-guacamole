CHRONOSPARK PROMPT BUILDER AUDIT
Date: 2026-07-31
Scope: prompt templates, system instructions, user prompt handling, grounding patterns, examples, constraints, tone, output formats, prompt safety, prompt duplication, and app-specific instruction quality.
Mode: Audit only. No code changes.

============================================================
SECTION 1: EXECUTIVE PROMPT SUMMARY
============================================================

Current prompt identity:
- ChronoSpark has several prompt-like surfaces, but the app is not a pure prompt-driven LLM app.
- The strongest live prompt systems are Smart Coach, SI Console, the shared chat/proxy system, and the SI/forecast helper outputs.
- Most prompt behavior is built from deterministic context, structured templates, and heuristic routing rather than a single central base prompt.

Where prompts are defined:
- Core Smart Coach instruction text lives in lib/state/controllers/coach_query_controller.dart.
- Shared prompt context builders live in lib/engine/assistant/assistant_context_builder.dart and lib/engine/assistant/assistant_interfaces.dart.
- The proxy system prompt lives in lib/data/services/ai/agents/chat_agent.dart.
- Shared response templates live in lib/engine/assistant/assistant_response_templates.dart.
- SI Console command copy and local prompt examples live in lib/features/si_console/ui/si_console_screen.dart.
- Tutorial and onboarding prompt-like copy lives in lib/tutorial/tutorial_content.dart and lib/features/onboarding/ui/onboarding_screen.dart.
- Forecast, planning, and progress guidance strings are spread across lib/state/providers/*, lib/engine/advisor/*, and lib/engine/si/*.

Which features use prompts:
- Smart Coach / Smart Planner-style guidance.
- SI Console commands and summaries.
- Future Vector / trajectory / forecast surfaces.
- Ascension-like progression, momentum, and identity helpers.
- Nexus / Home startup directive and summary copy.
- Tutorial / onboarding guidance and starter hints.
- Classification, summarization, reminder planning, and recommendation helpers.

Are prompts hardcoded, dynamic, reusable, or scattered:
- Hardcoded: yes, many user-facing prompt strings are embedded directly in screens and providers.
- Dynamic: yes, several surfaces build output from live task, goal, timeline, memory, profile, and momentum state.
- Reusable: partly, especially through assistant_context_builder.dart and assistant_response_templates.dart.
- Scattered: yes, especially in SI Console commands, forecast helper providers, tutorial copy, and narrative helpers.

Are prompts grounded in real app data:
- Mostly yes for Smart Coach, SI Console, and forecast helpers.
- More mixed for onboarding/tutorial copy, which is mostly instructional and not data-grounded.
- The biggest grounding gap is that several helper outputs feel factual even when they are derived heuristics, not real model inference.

Do prompts produce actionable outputs:
- Yes, generally.
- Smart Coach and SI Console usually recommend next actions, but some helper outputs are still explanatory rather than action-producing.
- Forecast surfaces often recommend one corrective action, which is good.

Does tone match ChronoSpark identity:
- Mostly yes for the mature surfaces: calm, direct, practical, and strategic.
- Weakest spots are the onboarding/tutorial and some login branding copy, which can feel more theatrical or militarized than the rest of the app.

Do prompt systems overlap or duplicate each other:
- Yes.
- Smart Coach, SI Console, Nexus startup copy, and several forecast helpers all express similar next-action guidance in different formats.
- The overlap is not necessarily wrong, but it does create repeated language and inconsistent levels of certainty.

Risk of hallucination from missing context:
- Medium overall.
- Lower in the local heuristic helpers, higher in the proxy-backed chat path because the prompt can be broad and the model may infer missing app facts.
- The most important mitigation is consistent context grounding and explicit "data missing" handling.

Overall verdict:
- REWIRE CONTEXT
- KEEP the grounded local-first prompt backbone.
- REFOCUS some surfaces that are more instructional than conversational.
- MERGE duplicated guidance patterns where possible.
- REWRITE LATER the most theatrical onboarding copy.

SECTION 3: SMART PLANNER PROMPT AUDIT
============================================================

What the user types:
- Free-form notes and follow-up questions in Smart Coach.
- Examples include "I'm tired", "lose weight", "stressed about work", and "what should I do next?" in lib/features/home/ui/smart_coach_screen.dart.

What system instructions exist:
- The strongest instruction is _smartCoachPolicy() in lib/state/controllers/coach_query_controller.dart.
- It says to detect intent category, never respond with generic encouragement alone, and output Goal Detected, Insight, Actions, Next Step, Momentum Score, Coach Question.
- ChatAgent adds another instruction: "Be concise, practical, and specific to the user context. Answer the newest message directly."

What app context is included:
- tasks, goals, memories, timeline, profile, progression, energy, emotion, core values, soul map, plan preview, reflection, and knowledge snapshots.
- The new shared ChronoSpark model context also includes completion, schedule, and routine summaries.

Are tasks included:
- Yes.

Are routines included:
- Partially now through shared ChronoSpark model context, but Smart Coach itself still mostly reads tasks and the broader knowledge bundle.

Are goals included:
- Yes.

Are notes included:
- Yes, through reflection text and memory summaries.

Are schedule/timeline included:
- Yes, timeline is included; schedule is indirectly represented via plan preview and scheduled task summaries.

Are completion history included:
- Partially.
- It now reaches the shared ChronoSpark model context and SI state, but the main Smart Coach policy still relies more on current context than explicit completion history.

Are profile context included:
- Yes.

Does the prompt tell the model to produce next actions:
- Yes.

Can the output become a task/routine/goal/note:
- Indirectly.
- The output recommends actions, but the app does not appear to have a direct prompt-to-Creator creation loop from the coaching surface alone.

Does the output route back to Creator or Timeline:
- Yes in spirit, but only indirectly through recommendations and voice handoff/navigation patterns.

Quality classification:
- grounded
- partially grounded
- not fully actionable as a creation loop

Smart Planner prompt readiness score:
- 78/100

Why not higher:
- The policy is strong, but the context bundle is still partially duplicated across surfaces.
- Some outputs still risk sounding generic if the user's context is thin.

SECTION 8: ONBOARDING / TUTORIAL PROMPT AND COPY AUDIT
============================================================

Main findings:
- Tutorial copy is mostly good: clear, calm, and workflow-aligned.
- The best lines are the ones that point back to Creator, Timeline, and simple actions.
- The weakest lines are the ones that feel broad or brand-heavy.

Good examples:
- "Scan energy, clarity, and momentum in one view, then choose one concrete next step."
- "Use Creator to build a task, goal, routine, or note when you need direct control."
- "Review what you created, scheduled, and completed so the next move stays obvious."
- "Send one focused prompt to get immediate guidance when momentum drops."

Prompt-copy gaps:
- The tutorial still uses a lot of feature names without telling the user exactly what to do.
- Some entries are more labels than guidance.
- The SoulMap hint text and some labels mix concepts a little awkwardly.

Aggressive or confusing language search results:
- In onboarding, the explicit "mission_zero_activation_started" and "mission_zero_activation_start_failed" phrases are analytics identifiers, not visible user prompts.
- The visible onboarding copy is relatively calm.
- The login header text "TEMPORAL INTELLIGENCE SYSTEM" is brand-heavy and slightly sci-fi, though not a prompt.

Should anything be softened:
- Yes, the branding around mission and temporal intelligence should be softened if the goal is calm, premium, user-first onboarding.
- The tutorial CTA language is mostly fine.

Recommended replacement style:
- clear
- calm
- practical
- user-first
- no forced AI usage
- no military language
- no fake urgency

Onboarding/tutorial prompt readiness score:
- 52/100

Why not higher:
- The workflow guidance is solid, but the copy is not fully consistent and sometimes leans into branded system language.
