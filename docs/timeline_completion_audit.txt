Timeline Completion Audit

Scope
- Inspected the Timeline screen, its providers, and the item action layer.
- Goal: determine what data appears on Timeline and whether completion, skip, and reschedule are supported.

Findings

1. What data appears on Timeline
- Timeline renders the base event stream from [lib/state/providers/timeline_provider.dart](lib/state/providers/timeline_provider.dart) through `timelineProvider`.
- Timeline also adds projected deadline-style events from current tasks and goals in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L61) and [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L1200).
- The visible event types supported by the Timeline event model include task, goal, habit, project, milestone, deadline, forecast, snapshot, risk, recommendation, reflection, level up, streak, and goal complete in [lib/domain/entities/timeline_event_entity.dart](lib/domain/entities/timeline_event_entity.dart).

2. Whether tasks appear
- Yes.
- Tasks are mirrored into Timeline when they are created via [lib/state/providers/task_provider.dart](lib/state/providers/task_provider.dart#L92).
- Timeline also projects task deadline items from the current task list in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L114) and [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L1200).
- Task-linked Timeline events are explicitly created with `TimelineEventType.task` in [lib/features/auth/domain/usecases/misc/connect_timeline_to_tasks_usecase.dart](lib/features/auth/domain/usecases/misc/connect_timeline_to_tasks_usecase.dart#L24).

3. Whether goals appear
- Yes.
- Goals are mirrored into Timeline through the goals timeline connector in [lib/state/providers/goals_provider.dart](lib/state/providers/goals_provider.dart#L1754).
- Timeline also projects goal deadline items from `goalsProvider` in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L113) and [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L1200).
- Goal-linked Timeline events are explicitly created with `TimelineEventType.goal` in [lib/features/auth/domain/usecases/misc/connect_timeline_to_goals_usecase.dart](lib/features/auth/domain/usecases/misc/connect_timeline_to_goals_usecase.dart#L18).

4. Whether routines appear
- Yes, but indirectly.
- Timeline does not have a dedicated routine event type.
- Routines are stored and surfaced as task-shaped entries, so they appear on Timeline the same way tasks do when they are created or projected.
- The screen only projects `Task` items and does not special-case a routine lane in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L114) and [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L1200).

5. Whether notes appear
- No dedicated note type appears on Timeline.
- There is no `TimelineEventType.note` in the event model.
- Note-like content can still appear as generic timeline snapshots or reflections when other parts of the app add them through `AddMemoryToTimelineUsecase` or `AddJournalToTimelineUsecase`, which create `snapshot` and `reflection` events respectively in [lib/features/auth/domain/usecases/misc/add_memory_to_timeline_usecase.dart](lib/features/auth/domain/usecases/misc/add_memory_to_timeline_usecase.dart#L21) and [lib/features/auth/domain/usecases/misc/add_journal_to_timeline_usecase.dart](lib/features/auth/domain/usecases/misc/add_journal_to_timeline_usecase.dart#L21).

6. Whether completion tracking exists
- Yes.
- Timeline has a completed-events provider in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L92).
- Timeline tiles can mark an item complete through `_completeTask()` in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L511).
- The Timeline event model also supports `TimelineEventStatus.completed` in [lib/domain/entities/timeline_event_entity.dart](lib/domain/entities/timeline_event_entity.dart).

7. Whether skipped status exists
- Yes.
- Timeline tiles can skip an item through `_skipTask()` in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L535).
- The action sets the local status to `TimelineEventStatus.planned`, and the status enum includes `planned` in [lib/domain/entities/timeline_event_entity.dart](lib/domain/entities/timeline_event_entity.dart).

8. Whether reschedule exists
- Yes.
- Timeline tiles can reschedule an item through `_rescheduleTask(Duration by)` in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L544).
- The Timeline action row exposes preset reschedule choices for +2h, +1d, and +1w in [lib/features/timeline/ui/timeline_screen.dart](lib/features/timeline/ui/timeline_screen.dart#L609).

Bottom line
- Timeline is task-and-goal aware, with projected deadline items and live item actions.
- Tasks and goals appear directly; routines appear through the task path; notes do not have a dedicated Timeline lane, but can surface as snapshot/reflection events if mirrored in from other flows.
- Completion, skipped/planned status, and reschedule are all present.

Page Builder Feedback

What works
- The page already has a clear temporal spine: base events, projected deadlines, and intelligence cards are layered in a way that can support a stronger editorial layout.
- The action row gives Timeline real utility instead of making it a passive feed.
- Goal and task projection means the page can function as a planning surface, not just an event log.

What needs improvement
- The screen still reads like a dense console. The hierarchy should be more explicit so the user can tell what is primary, secondary, and contextual at a glance.
- Tasks and goals are both present, but they are not yet visually separated enough to feel like distinct lanes.
- Notes are not first-class Timeline content, so they can feel incidental when they appear as snapshots or reflections.
- Intelligence cards are useful, but they can overpower the page if too many are shown together.

Recommendations
1. Promote one primary story per window.
- For example: Today should foreground next actions, Week should foreground deadlines, and All should foreground historical context.

2. Separate execution from outcome.
- Tasks should read as things to do, while goals should read as things to achieve.
- If both stay on the same page, use stronger labels, badges, or grouping to make the distinction obvious.

3. Treat notes as support content, not core timeline content.
- If notes remain on Timeline, label them clearly as snapshots or reflections so they do not blur the planning model.

4. Keep the action model narrow.
- Complete, skip, and reschedule are the right controls for task-like items.
- Goal-like items should continue to use goal-oriented actions rather than inheriting task behavior.

5. Reduce repeated intelligence surfaces.
- Snapshot, risk, and recommendation cards should be scoped so they inform the page without turning it into a telemetry wall.

6. Make empty and low-content states constructive.
- When Timeline has little data, it should guide the user toward creating the next task, goal, or scheduled item.

7. Let Timeline act as a connector.
- The page is strongest when it previews what matters now and routes the user into Creator, Goals, or task detail views for deeper editing.

Overall feedback
- Timeline is already a credible planning page.
- To feel like a true page builder, it needs stronger hierarchy, clearer separation of content types, and a more intentional narrative around what the user should do next.
