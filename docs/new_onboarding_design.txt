New Onboarding Design

Purpose
- Design-only proposal for a clearer onboarding experience.
- Goal: teach the user how to create a task, goal, routine, or note; choose frequency; choose a date; save; view Timeline; and mark complete.
- No implementation changes are included in this document.

Compare With Current Onboarding System
- Current onboarding is effectively a setup gate with one page in [lib/features/onboarding/ui/onboarding_screen.dart](lib/features/onboarding/ui/onboarding_screen.dart).
- The app also uses mission/tutorial vocabulary in [lib/tutorial/mission/mission_state.dart](lib/tutorial/mission/mission_state.dart) and [lib/tutorial/tutorial_content.dart](lib/tutorial/tutorial_content.dart).
- The current flow is mostly about activation and routing, not teaching the full Creator-to-Timeline loop.
- The proposed design turns onboarding into a guided product lesson that teaches the actual workflow the user will use after setup.

Design Goals
- Keep the product feeling like one coherent planning system.
- Teach by doing, not by explaining everything up front.
- Show only the minimum controls needed for each step.
- Reinforce the loop: create -> schedule -> save -> review on Timeline -> complete.
- Keep the experience lightweight enough that the user can finish onboarding quickly.

Proposed Onboarding Structure
- Step 1: Create an item.
- Step 2: Choose frequency.
- Step 3: Choose date.
- Step 4: Save.
- Step 5: View Timeline.
- Step 6: Mark complete.

Step-by-Step Design

1. Create task / goal / routine / note
- Screen intent: teach the user that Creator supports multiple item types.
- UI focus: type selector first, then title field.
- Microcopy:
  - Task: a one-time action.
  - Goal: an outcome you want to reach.
  - Routine: a repeating action.
  - Note: a captured thought or memory.
- Interaction pattern:
  - User selects one type.
  - The form adapts copy and hints to that type.
- Success state:
  - The selected type is clearly acknowledged before moving to the next step.

2. Choose frequency
- Screen intent: teach repeat behavior without overwhelming the user.
- UI focus: frequency selector with only the needed choices.
- Microcopy:
  - Once.
  - Every day.
  - Every week.
- Interaction pattern:
  - Choosing a routine visually emphasizes repetition.
  - Choosing task or goal keeps the default at one-time unless the user changes it.
- Success state:
  - User understands that frequency controls recurrence, not priority.

3. Choose date
- Screen intent: teach when the item happens or is due.
- UI focus: date picker or target date selector.
- Microcopy:
  - Pick when this should happen.
  - For goals, this is the target date.
  - For tasks and routines, this is the schedule date.
- Interaction pattern:
  - Show one calendar control.
  - If frequency is repeating, the date is framed as the start or next occurrence.
- Success state:
  - User sees that date is part of planning, not a separate admin task.

4. Save
- Screen intent: teach that the item is now part of the system.
- UI focus: single primary save button.
- Microcopy:
  - Save item.
  - Add to Timeline.
- Interaction pattern:
  - After save, show a brief confirmation that the item exists and is ready for review.
- Success state:
  - The user knows the item has been stored and is not just a draft.

5. View Timeline
- Screen intent: show that saved items appear in Timeline as the review surface.
- UI focus: automatic or prompted transition to Timeline.
- Microcopy:
  - Review it on Timeline.
  - See how it appears in your plan.
- Interaction pattern:
  - Open Timeline immediately after the first successful save when appropriate.
  - Highlight the new event or projected deadline.
- Success state:
  - User understands Timeline is the place to verify and manage what they created.

6. Mark complete
- Screen intent: teach the closing action loop.
- UI focus: a visible completion action on the Timeline item.
- Microcopy:
  - Mark complete.
  - Finish this step.
- Interaction pattern:
  - The first completed item should be easy to locate and tap.
  - Show a small confirmation after completion.
- Success state:
  - User experiences the full loop from creation to closure.

Proposed User Flow
- Welcome / explanation.
- Create the first item.
- Choose frequency.
- Choose date.
- Save.
- Jump to Timeline.
- Mark complete.
- Confirm success.

Current System Versus Proposed System
- Current system:
  - A compact setup gate.
  - Mission overlay for progress.
  - Tutorial vocabulary scattered across several files.
  - Strong activation, weaker teaching.
- Proposed system:
  - One guided onboarding narrative.
  - One workflow that mirrors the actual product path.
  - Less setup language, more product teaching.
  - Clearer reinforcement of Creator and Timeline.

Content Direction
- Use simple, action-oriented labels.
- Prefer Create, Schedule, Save, Review, Complete.
- Avoid heavy mission jargon for the onboarding lesson itself.
- Keep the teaching language aligned with the app vocabulary already used in Creator, Timeline, and mission steps.

Visual Direction
- Use a calm, high-contrast step-by-step layout.
- Show one primary action per screen.
- Use progress indicators that make the flow feel short and finite.
- Keep the final confirmation celebratory but restrained.

Risk Notes
- Do not make onboarding feel like a separate app inside the app.
- Do not overload the user with all item types at once unless that is intentional for the design.
- Do not add extra tutorial layers on top of the flow unless they reduce confusion.

Recommended Final Shape
- A short guided onboarding sequence that teaches the Creator-to-Timeline loop.
- The onboarding should end by proving that the item exists on Timeline and can be completed there.
- This keeps the system credible, learnable, and directly tied to real app behavior.
