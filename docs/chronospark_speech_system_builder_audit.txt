SECTION 19
TARGET CHRONOSPARK SPEECH ARCHITECTURE
============================================================

SAFE SAFE target architecture:
- Layer 1: Capture (bounded entry)
  - User-initiated tap-to-listen only.
  - One-session capture window; no always-on background listening.
  - Permission gate required before any capture start.
- Layer 2: Recognition (bounded transform)
  - Convert speech to transient text.
  - Keep partial/final recognition state scoped to active UI session.
  - Emit machine-readable status and error outcomes.
- Layer 3: Intent & entity extraction
  - Parse intent family: creator, timeline-read, timeline-action, planner, SI summary.
  - Extract entities: title, date/schedule, recurrence, target, action verb.
  - Attach confidence class: high, medium, low.
- Layer 4: Safety policy engine
  - Route read-only intents directly to read-safe handlers.
  - Route write-like intents to explicit UI confirmation gates.
  - Block ambiguous or low-confidence write-like intents.
- Layer 5: Handoff and UI prefill
  - Deliver structured handoff payload to Creator/Timeline surfaces.
  - Prefill fields without silently committing mutations.
- Layer 6: Spoken output (TTS)
  - Return concise confirmations and summaries.
  - Enforce brevity profiles by surface (Planner, Timeline, SI Console).
- Layer 7: Telemetry and auditability
  - Capture intent, confidence class, route, confirmation result, and fallback reason.
  - Never log secrets, raw audio, or sensitive payload text by default.

Speech output targets:
- Daily Briefing: concise priorities + due summary + next-best action.
- Timeline Summary: today/overdue counts with top actionable items.
- Progress Summary: ascension and completion stability snapshot.
- Future Vector Summary: compact risk/opportunity outlook.

Ideal SAFE SAFE data flow:
- Mic tap -> permission gate -> STT -> intent/entity extraction -> safety policy -> UI confirmation (if write-like) -> state mutation -> TTS response -> telemetry.

Architecture principles:
- UI is source of truth for any mutation.
- Speech is acceleration, not authority.
- Privacy by default with explicit user controls.
- Fail closed on uncertain write-like commands.

SECTION 20
SAFE SPEECH ROADMAP
============================================================

SAFE SAFE upgrade roadmap:

Global controls for every phase:
- Feature flags: enable by surface and user cohort.
- Kill switch: instant disable for STT entry, command execution, and TTS by channel.
- Release gate: 0 critical regressions, 0 unauthorized mutations, stable crash/error rate.
- Rollback trigger: permission failures spike, intent-misroute spike, or mutation safety breach.

Phase 1: Baseline lock and observability hardening
- Goal: freeze known-good behavior and tighten telemetry for speech outcomes.
- Scope files:
  - lib/state/controllers/voice_controller.dart
  - lib/system/voice/voice_service.dart
  - lib/state/providers/voice_command_provider.dart
  - lib/state/providers/voice_command_handoff_provider.dart
- Safety gate to exit phase:
  - All intents produce deterministic route classification.
  - Error/fallback telemetry present for each failed command.
- Risk level: low.

Phase 2: Creator dictation structure upgrade
- Goal: convert schedule/frequency hints into deterministic structured prefill proposals.
- Scope files:
  - lib/features/home/ui/smart_coach_screen.dart
  - lib/state/providers/voice_command_provider.dart
  - lib/state/providers/voice_command_handoff_provider.dart
  - lib/features/creator/ui/creator_screen.dart
  - lib/features/creator/widgets/dynamic_form.dart
- Safety gate to exit phase:
  - No silent writes; UI preview required before save.

- Risk level: medium.

Phase 3: Timeline read-first command strengthening

- Scope files:
