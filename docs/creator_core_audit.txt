CREATOR CORE AUDIT
Date: 2026-07-30
Mode: Audit only (no code changes)
Scope: Determine whether Creator can already support Task, Goal, Routine, Note, One-time scheduling, Daily repeat, Weekly repeat.

============================================================
EXECUTIVE RESULT
============================================================
Overall: Creator already supports all requested entry types and recurrence options at the form and persistence layers.

Status by requirement:
- Task: Exists
- Goal: Partially wired
- Routine: Exists
- Note: Exists
- One-time scheduling: Exists
- Daily repeat: Exists
- Weekly repeat: Exists

============================================================
WHAT ALREADY EXISTS
============================================================
1) Task support: EXISTS
- Type selection includes Task in Creator type selector.
- Creator submit pipeline persists task entries through createEntry -> TaskEntity.
- Evidence:
  - lib/features/creator/widgets/type_selector.dart
  - lib/features/creator/widgets/dynamic_form.dart
  - lib/state/providers/creator_provider.dart

2) Routine support: EXISTS
- Type selector includes Routine.
- Routine defaults recurrence to daily when recurrence is unset.
- Recurrence can still be manually changed by user.
- Evidence:
  - lib/features/creator/widgets/type_selector.dart
  - lib/features/creator/widgets/dynamic_form.dart
  - lib/state/providers/creator_provider.dart

3) Note support: EXISTS
- Type selector includes Note.
- Note uses note-oriented detail field copy and persists as kind note.
- Evidence:
  - lib/features/creator/widgets/type_selector.dart
  - lib/features/creator/widgets/dynamic_form.dart
  - lib/state/providers/creator_provider.dart

4) One-time scheduling support: EXISTS
- Recurrence chip includes One-time mapped to RecurrenceRule.none.
- Schedule date picker sets scheduledFor date.
- TaskEntity stores scheduledFor and recurrenceRule.
- Evidence:
  - lib/features/creator/widgets/dynamic_form.dart
  - lib/domain/entities/recurrence_rule.dart
  - lib/domain/entities/task_entity.dart

5) Daily repeat support: EXISTS
- Recurrence chip includes Every day -> RecurrenceRule.daily.
- Completion use case creates next recurring occurrence for recurring tasks.
- Planning engine expands daily occurrences for planning horizon.
- Evidence:
  - lib/features/creator/widgets/dynamic_form.dart
  - lib/domain/usecases/complete_task.dart
  - lib/engine/planning/calendar_service.dart

6) Weekly repeat support: EXISTS
- Recurrence chip includes Every week -> RecurrenceRule.weekly.
- Completion use case generates next instance with weekly offset.
- Planning engine computes weekly occurrence alignment.
- Evidence:
  - lib/features/creator/widgets/dynamic_form.dart
  - lib/domain/usecases/complete_task.dart
  - lib/engine/planning/calendar_service.dart

============================================================
WHAT IS PARTIALLY WIRED
============================================================
1) Goal support: PARTIALLY WIRED
- Creator form allows Goal type and persists entries with kind goal.
- However, Creator writes through TaskEntity pipeline, not GoalEntity creation path.
- Dedicated goals domain/provider stack exists separately, indicating dual-path semantics.
- Practical impact: goal-like creation works, but it is not a fully unified GoalEntity-native create path from Creator.
- Evidence:
  - lib/features/creator/widgets/type_selector.dart
  - lib/state/providers/creator_provider.dart
  - lib/state/providers/goals_provider.dart

============================================================
WHAT IS MISSING
============================================================
For the exact requested checklist, no capability is completely missing.

Clarification on remaining gap:
- The only notable gap is not absence of Goal creation UX, but architectural split between TaskEntity(kind=goal) and dedicated GoalEntity workflows.
