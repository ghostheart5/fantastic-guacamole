================================================================================
EXECUTIVE SUMMARY
================================================================================
The first-run architecture is strongly guarded and deterministic, but it has a high-risk progression deadlock in the current setup:
- Onboarding completion is finalized by mission completion.
- Mission progression requires Smart Planner question + Timeline open.
- While onboarding is incomplete, route + shell gating forces Creator and blocks non-allowed surfaces.
- Result: users can remain permanently in "incomplete onboarding" state unless a side-path unlocks mission advancement.

What works well:
- Predictable startup and redirect chain.
- Safe auth fallback behavior.
- First-create and first-timeline-action onboarding signals are persisted with per-user keys.

Highest risk:
- Flow can become trapped at Creator due to combined mission progression and routing constraints.

================================================================================
PRIMARY FLOW LOGIC (OBSERVED)
================================================================================
1) Startup state load
- Startup bootstrap reads onboarding + first-item flags and sets runtime providers.
- If prefs load fails/times out, status becomes unknown/incomplete-safe defaults.

2) Initial location resolver
- unknown onboarding -> /onboarding
- onboarding incomplete + authenticated -> /creator
- onboarding incomplete + logged out -> /onboarding
- onboarding complete + logged out -> /login
- onboarding complete + authenticated + no first item -> /creator
- onboarding complete + authenticated + first item but no timeline first action -> /timeline
- otherwise -> /home

3) Global redirect guard
- Incomplete onboarding blocks most routes and redirects to /onboarding,
  except mission activation surfaces (/home, /, /creator) for authenticated users.
- Login while incomplete onboarding is blocked unless recovery/auth callback modes.

4) Navigation shell enforcement
- If onboarding status is incomplete, required view is Creator.
- If onboarding complete but no first item, required view is Creator.
- If first item exists but no timeline first action, required view is Timeline.

SCENARIO ANALYSIS (REQUESTED 1-9)
================================================================================

1. Fresh install
- First screen:
  - Startup loader first, then /onboarding.
- First required action:
  - Start setup (onboarding start action).
- Can create immediately?
  - No (not before setup transition).
- Can user get trapped?
  - Yes, potential trap after setup start if mission progression cannot complete.
- Is Smart Planner forced?
  - Not by route directly; mission progression expects Smart Planner question event.
- Is Timeline forced?
  - Not initially; later forced by route only after onboarding complete + first item.
- Is Action Hub mentioned?
  - No visible UX mention.
- Is old Mission Zero language visible?
  - Not as primary UI title; legacy/internal names still present.

2. Logged-out user
- First screen:
  - /onboarding if onboarding incomplete.
  - /login if onboarding already complete.
- First required action:
  - Either continue setup (if incomplete) or authenticate (if complete).
- Can create immediately?
  - No.
- Can user get trapped?
  - Medium risk when onboarding incomplete and login mode not exempt.
- Smart Planner forced?
  - No direct route force.
- Timeline forced?
  - No direct route force in logged-out state.

3. First login
- First screen after auth:
  - Redirected by router to /creator while incomplete onboarding.
- First required action:
  - Create first item (Creator path).
- Can create immediately?
  - Yes, once authenticated and on Creator.
- Can user get trapped?
  - Yes, if onboarding remains incomplete and mission progression cannot advance.
- Smart Planner forced?
  - Indirect mission dependency, not route-force.
- Timeline forced?
  - Not while onboarding incomplete.

4. Incomplete onboarding
- First screen:
  - /onboarding for most entries.
  - /creator allowed for authenticated mission activation corridor.
- First required action:
  - Setup progression and Creator engagement.
- Can create immediately?
  - Authenticated: yes on Creator.
  - Logged-out: no.
- Can user get trapped?
  - Yes (high risk): shell keeps requiring Creator while incomplete.
- Smart Planner forced?
  - Not route-forced; mission step requires related event.
- Timeline forced?
  - Not route-forced in incomplete onboarding.

5. Completed onboarding
- First screen:
  - If no created item -> /creator.
  - If created item but no timeline first action -> /timeline.
  - Else -> /home.
- First required action:
  - Create first item if missing.
  - Then perform timeline first action if missing.
- Can create immediately?
  - Yes.
- Can user get trapped?
  - Low to medium; mostly guided/forced but deterministic.
- Smart Planner forced?
  - No.
- Timeline forced?
  - Yes, if first timeline action not complete.

6. Returning user
- First screen:
  - Route resolution based on persisted flags, then session recovery may restore prior tab/view
    (subject to activation enforcement).
- First required action:
  - Depends on saved gating flags.
- Can create immediately?
  - Usually yes if routed to Creator or Home with Creator available.
- Can user get trapped?
  - Medium if onboarding status remains incomplete.
- Smart Planner forced?
  - No.
- Timeline forced?
  - Conditional on first timeline action flag.

7. User with existing saved mission/tutorial state
- First screen:
  - Same router flow as above; mission state overlays progress cues.
- First required action:
  - Resume active mission step from persisted mission_tutorial_progress_v1.
- Can create immediately?
  - Usually yes if Creator is active route.
- Can user get trapped?
  - High if mission step order conflicts with route/shell locks.
- Smart Planner forced?
  - Mission progression expects Smart Planner question event.
- Timeline forced?
  - Mission progression expects timeline-open event; route forcing varies by onboarding status.

8. User with no created items
- First screen:
  - /creator (when authenticated/onboarded or onboarding incomplete + authenticated).
- First required action:
  - Create first item.
- Can create immediately?
  - Yes.
- Can user get trapped?
  - Low for create action itself; higher if onboarding completion depends on later blocked steps.
- Smart Planner forced?
  - No direct force.
- Timeline forced?
  - After onboarding complete and first item set, yes if first timeline action not complete.

9. User with created items
- First screen:
  - If timeline first action incomplete -> /timeline.
  - Otherwise -> /home.
- First required action:
  - Complete first timeline action when required.
- Can create immediately?
  - Yes (Creator available through shell/map).
- Can user get trapped?
  - Low when onboarding complete; medium if onboarding still incomplete.
- Smart Planner forced?
  - No direct force.
- Timeline forced?
  - Yes when first timeline action flag is false and onboarding complete.

================================================================================
DIRECT ANSWERS TO REQUESTED QUESTIONS
================================================================================

What is the first screen?
- Startup loader (bootstrap gate), then router-driven destination:
  /onboarding, /creator, /timeline, /home, or /login depending on state.

What is the first required action?
- For true first-run: begin setup, then create first item.
- For onboarded but not initialized users: create first item, then perform first timeline action.

Can the user create something immediately?
- Logged-out: no.
- Authenticated with allowed route: yes (Creator is first forced surface in most first-run states).

Can the user get trapped?
- Yes (high-risk path): incomplete onboarding + mission completion dependency + Creator-only shell enforcement.

Is Smart Planner forced?
- Not as a route redirect target.
- Mission progression expects Smart Planner question completion event.

Is Timeline forced?
- Yes, conditionally:
  - onboarding complete
  - hasCreatedFirstItem=true
  - hasCompletedTimelineFirstAction=false

Is Action Hub mentioned?
- Only code-level legacy alias mapping: openActionHub -> configureFirstItem.
- Not found as active user-facing label in the reviewed flow files.

Is old Mission Zero language visible?
- Yes in code/telemetry identifiers and method names (for example mission_zero_activation_*).
- Mission terms also appear in visible Nexus sync text ("MISSION SYNC").

What state flags control the flow?
- OnboardingStatus (unknown/incomplete/complete)
- onboardingCompleteProvider
- creatorFirstItemCreatedProvider
- timelineFirstActionCompletedProvider
- authenticatedGuardProvider
- profileCompleteGuardProvider
- mission tutorial state (MissionState active/finished)
- mock login / QA skip flags in router conditions

What storage keys affect the flow?
Onboarding/activation keys:
- onboarding_complete
- onboarding_content_version
- onboarding_step_index
- onboarding_state_v1
- creator_first_item_created_v1
- timeline_first_action_completed_v1
- per-user variants of all above (suffix _<userId>)

Mission/tutorial keys:
- mission_tutorial_progress_v1
- tutorial_progress_v1

Session recovery keys:
- rec_last_route
- rec_active_task
- rec_draft_title

What route redirects affect the flow?
- Initial resolver selects onboarding/login/creator/timeline/home by state.
- Global redirect enforces onboarding and login constraints.
- /login redirects away if authenticated.
- /home redirects to /creator if first item missing.
- Any route redirects to /timeline when timeline-first-action is required.
- Incomplete onboarding blocks most routes except authenticated activation corridor.

================================================================================
KEY RISK FINDINGS
================================================================================
Risk A (Critical): Potential first-run progression deadlock
- Onboarding completion finalization depends on mission finished state.
- Mission progression requires Smart Planner + Timeline steps.
- Incomplete onboarding enforcement keeps user in Creator path.

Risk B (High): Legacy naming still embedded in activation flow
- Mission Zero and mission/activation terms remain in critical first-run logic and telemetry.

Risk C (Medium): Route intent and naming mismatch
- Home/Nexus/Creator/insights naming and activation corridor logic can feel inconsistent to first-time users.
