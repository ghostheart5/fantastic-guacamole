============================================================
SECTION 1
EXECUTIVE VOICE SUMMARY
============================================================

Current voice maturity:
- MODERATE for navigation + spoken feedback.
- WEAK for end-to-end workflow execution by voice (especially timeline actions and schedule/frequency capture).

Current speech systems:
- Speech-to-text exists via speech_to_text in VoiceController.
- Mic interaction is manually invoked (tap-to-listen), not always-on.

Current TTS systems:
- Text-to-speech exists via flutter_tts in VoiceService.
- TTS is actively used in Smart Planner and SI Console for spoken responses/recaps.

Current voice interaction systems:
- Voice command parser supports route/navigation intents and creator entry intent handoff.
- Creator handoff can prefill title/memory text, but does not capture schedule/frequency via voice.

Verdict:
- MODERATE

============================================================

Ideal command design (do not implement):

- "Create a task [title]"
- "Create a goal [title]"
- "Create a routine [title] every weekday at 7 AM"
- "Create a note [details]"

Timeline:
- "Show today"
- "Show overdue"
- "Complete task [title or index]"
- "Skip task [title or index]"
- "Move task [title or index] to tomorrow"

Smart Planner:
- "Help me plan today"
- "What should I do next"

Model guidelines:
- Confirm intent before write actions.
- Prefer explicit nouns + modifiers (task name, day/time, recurrence).
- Never hide action side effects; always respond with a concise confirmation.

AI privacy concerns:
- Spoken content that becomes query text may inherit AI/privacy handling risks of text inputs.
- Clear user messaging and explicit consent boundaries are required.

Flagged risks:
- Incomplete permission service implementation.
- Possible mismatch between spoken confirmations and actual command execution path for unknown commands.
- No explicit in-scope transcript retention policy controls visible in reviewed files.

SECTION 15
TARGET CHRONOSPARK VOICE MODEL
============================================================

Core principle:
- Voice accelerates Create -> Schedule -> Review -> Complete.
- Voice never replaces the UI.

Ideal architecture:
- Layer 1: Input capture
  - tap-to-listen STT only
  - explicit start/stop capture

- Layer 2: Intent + entity parsing
  - parse intent (create/review/complete/skip/reschedule)
  - parse entities (title, date, time, recurrence)

- Layer 3: Safety confirmation
  - read back action in one sentence
  - require confirm for write actions

- Layer 4: UI handoff
  - navigate to target surface with prefilled values
  - keep visual controls primary for final edits

- Layer 5: Optional spoken output
  - short TTS summaries for recap and accessibility

Voice should not become:
- A gimmick
- A phone tree
- A mandatory interface
