SECTION 4
PIPELINE ARCHITECTURE ASSESSMENT
============================================================

Observed architecture pattern:
- Hybrid pipeline.
- Deterministic state-derived generation is used for many critical responses.
- AI-assisted generation is invoked for open-ended conversational requests.

Strengths:
- Controller boundaries are explicit.
- Data aggregation via providers keeps generation grounded in app state.
- Fallback logic prevents empty or low-quality AI outputs from leaking directly.

Risks:
- Multiple layers can make behavior hard to reason about without strong telemetry tags.
- Large context objects may produce non-essential verbosity.

Assessment:
- Architecture is directionally strong for a planner product.
- Needs stronger traceability and tighter response budgets.

Score:
- 82/100

============================================================

Findings:

- Smart Coach and SI Console each route through dedicated detection logic.

SAFE upgrades:

- Add regression tests for mixed-intent prompts and edge phrasing.

SECTION 17
SAFE UPGRADE ROADMAP (AUDIT RECOMMENDATIONS ONLY)
============================================================

SAFE SAFE ROADMAP PRINCIPLES
- Keep deterministic safety paths active at all times.
- Ship only measurable hardening, not new generation capabilities.
- Use gated rollout with explicit stop conditions.

Phase A: Instrument and Measure (safe)
- Add analytics counters and metadata tags for route, fallback, and response structure quality.
- Add surface-level latency metrics and timeout-rate reporting.

Phase A gate (must pass before Phase B)
- Metrics available by surface: smart_coach, si_console, trajectory/future.
- Baseline captured for 7 days of normal usage.
- No regression in crash-free sessions for audited surfaces.

Phase B: Routing and Safety Hardening (safe)
- Expand intent edge-case tests.
- Expand crisis phrase coverage tests and multilingual phrase corpus.

Phase B gate (must pass before Phase C)
- Mixed-intent routing tests pass at 100% in CI.
- Crisis-detection regression suite passes with no critical misses.
- No increase in timeout_rate versus Phase A baseline.

Phase C: Privacy and Context Minimization (safe)
- Define explicit minimum context contracts per surface.
- Add retention labels and audit logging for persisted conversational turns.

Phase C gate (must pass before Phase D)
- Context payload size reduced or held stable with no quality drop.
- Stored-conversation retention policy documented and enforced.
- No new sensitive fields introduced into generation context.

Phase D: Operational Governance and Release Lock (safe)
- Publish content-generation SLO thresholds and release gate checks.
- Add policy/version trace IDs for every generated response.

Phase D gate (final pre-release)
- Release checklist includes: secret scan pass, prompt contract pass, routing tests pass, crisis tests pass, latency budget pass.
- Go/no-go signoff by engineering owner and product owner.

Stop conditions (automatic hold)
- fallback_rate rises >20% over baseline for 2 consecutive days.
- timeout_rate rises >15% over baseline for 2 consecutive days.
- Any critical crisis-path regression is detected.
- Any secret-hygiene release test fails.

Rollback conditions (safe rollback)
- Revert to last known-good release build when any stop condition triggers.
- Keep deterministic response templates active during rollback.

Non-goals for this roadmap:
- No new AI features.
- No prompt rewrites during this audit task.
- No unsafe expansion of user-data context scope.
