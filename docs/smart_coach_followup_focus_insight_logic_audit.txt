FINDINGS (ordered by severity)

[High] Follow-up input is cleared before network success, causing user input loss on timeout/error
- Location: Smart Coach follow-up send path in smart_coach_screen.dart
- Evidence:
  - text is read from controller
  - controller is cleared immediately before async request finishes
  - timeout/error handlers show failure messages but do not restore text
- Impact:
  - On timeout/failure, user loses typed follow-up and must retype.
  - This degrades UX and can reduce successful follow-up completion.
- Recommendation:
  - Clear controller only after successful response, or restore the original text on failure.

[Medium] Follow-up history truncation uses entry count, not conversation turns, reducing context depth unpredictably
- Location: smart_coach_conversation_state.dart, toHistory(maxEntries: 8)
- Evidence:
  - history stores alternating user/assistant entries
  - truncation keeps last N entries, not last N turns
- Impact:
  - Effective context may vary and can clip one side of older turns depending on count.
  - Can lower answer continuity on longer follow-up sessions.
- Recommendation:
  - Truncate by full turns (pairs) or increase cap while preserving latency budget.

[Medium] Insight messaging can diverge between hero and smart insight panel sources
- Location: smart_coach_screen.dart (effectiveCoachMessage + explainableSIProvider block)
- Evidence:
  - hero/primary insight uses effectiveCoachMessage from _coachingMessage or model decision
  - explanation card uses explainableSIProvider (momentum/briefing derived)
- Impact:
  - Users may see a coaching message and explanation reasoning that do not perfectly align in wording/source timing.
- Recommendation:
  - Add source/time consistency cue or bind explainable reasoning to the same recommendation payload when available.

[Low] Focus Context capture is clear and wired correctly, but input constraints may limit long-form reflection
- Location: smart_coach_screen.dart FOCUS CONTEXT panel
- Evidence:
  - TextField uses _notesController with minLines/maxLines compact limits
  - onChanged toggles _saved=false
  - notes are passed into requestCoaching and reflection for requestFollowUp
- Impact:
  - Behavior is correct; only potential UX limitation for very long notes.
- Recommendation:
  - Keep compact defaults; consider optional expand affordance if long-form reflection becomes common.

DEEP AUDIT BY REQUESTED TOPIC

1) Follow-up Question Flow
- Entry point:
  - _sendFollowUp() in smart_coach_screen.dart
- Input wiring:
  - reads _followUpController.text.trim()
  - blocks empty input
  - crisis check via coach.detectsCrisis(text)
- Request wiring:
  - calls coachQueryControllerProvider.requestFollowUp(
      input,
      energy,
      emotion,
      reflection: _notesController.text.trim(),
      history: _conversationHistory()
    )
  - 25s timeout
- Output wiring:
  - success appends SmartCoachExchange(question, answer)
  - updates UI state, speaks reply, scrolls to bottom
  - timeout/error sets _followUpError
- Use cases and dependencies used:
  - CrisisDetectionPolicy (via detectsCrisis)
  - AI orchestration and deterministic fallback in CoachQueryController
  - content generation analytics and release gate telemetry
  - persisted conversation turns through controller internals
- Key risk:
  - input is cleared before request success (high severity UX regression risk)

2) Focus Context Flow
- Entry point:
  - FOCUS CONTEXT TextField in smart_coach_screen.dart
- Input wiring:
  - controller: _notesController
  - onChanged marks _saved=false
  - helper text added to guide user input
- Downstream use:
  - _doGetCoaching(): notes passed as primary prompt context
  - _sendFollowUp(): notes passed as reflection context
  - _logEmotionCheckIn(): notes included in timeline emotion detail
- Output effect:
  - influences detected topic, assistant context, and fallback response
  - may be persisted as SI reflection when changed
- Use cases and dependencies used via controller:
  - workspaceStoreService append SI reflection
  - memoriesActionsProvider save mirrored memory
  - assistant context builders and ChronoSpark prompt policy
- Assessment:
  - wiring is coherent and behaviorally correct

3) Insight Flow
- Entry points:
  - _getCoaching() -> _doGetCoaching()
  - smartCoachScreenModelProvider for model-backed fallback message
  - explainableSIProvider for "Why this action?" reasoning
- Input wiring:
  - energy, emotion, notes, history, previousSavedNotes
- Use case/controller path:
  - CoachQueryController.requestCoaching()
  - topic detection + route resolution:
    - deterministic local structured response for non-general topics
    - AI orchestrated path for general chat
  - fallback guards:
    - non-actionable AI detection
    - structured response validation
- Output wiring:
  - result.message -> _coachingMessage and UI
  - smart hero receives effectiveCoachMessage + nextAction
  - explanation panel receives explainable.primaryReason/reasons/recommendation
- Additional side effects:
  - timeline emotion event logged asynchronously
  - XP increment on successful coaching path in controller
  - conversation turn persistence for user and assistant
- Assessment:
  - robust multi-path design with safety/fallback logic
  - moderate consistency risk between recommendation text and explainable rationale source

OVERALL VERDICT
- Core logic and wiring are solid and feature-complete for focus context, insight generation, and follow-up orchestration.
- Highest-priority fix is preserving follow-up input on failed requests.
- Secondary improvement is history truncation strategy for long sessions and messaging-source consistency between coaching text and explanation panel.
