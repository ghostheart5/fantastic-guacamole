CHRONOSPARK WORKFLOW / PROCESS BUILDER AUDIT
Date: 2026-07-30
Mode: Audit only. No code changes.
Scope: Mobile app workflows and processes only. This report covers creator flows, timeline review, completion, routines, goals, notes, onboarding, profile/settings, subscription/payment, notifications/reminders, Supabase workflow touchpoints, and process handoffs.

============================================================
SECTION 1: EXECUTIVE WORKFLOW SUMMARY
============================================================
Main workflow today:
- Login -> Creator or Timeline -> create task/goal/routine-like item -> Timeline review -> task completion side effects -> progression/intelligence updates.
- In practice, the app is strongest around task/goal creation and task completion. Many other workflow labels are routed through existing task or intelligence surfaces rather than dedicated process modules.

Intended main workflow:
- Login -> create task/routine/goal/note in Creator -> choose timing and date -> Create -> appear on Timeline -> mark completed/not completed/skipped/rescheduled -> feed Ascension, Future Vector, Smart Planner, and SI Console.

Clear create to schedule to review to complete process?
- Partially yes. The task/goal path is clear. Scheduling exists. Timeline review exists. Completion exists. Routine and note are only partially modeled and are not first-class processes.

Where the process breaks:
- Routines and notes do not have dedicated feature folders or native lifecycle flows.
- Timeline review is strong for tasks but weaker for routine/note semantics.
- Completion has a strong task path, but “not completed” is implemented as delay/move-forward, not a distinct status model.
- Onboarding exists as multiple overlapping systems, with some usecase shells still unused.
- Subscription and profile/settings are navigable, but workflow ownership is split across multiple repositories and screens.

Workflow style:
- Mixed. User-driven at the point of create/decision, system-driven in side effects, logs, progression, and derived intelligence.

Duplicate workflows:
- Onboarding exists across onboarding screen, mission state, tutorial controller, bootstrap flags, and route guards.
- Smart Planner, Future Vector, Ascension, and SI Console are heavily represented through derived providers and Nexus surfaces rather than dedicated end-to-end process modules.

Dead-end workflows:
- Routine and note creation do not land in dedicated native lifecycle systems.
- Empty onboarding usecases are shells and do not currently drive runtime flow.

Workflows that start but never complete:
- Some onboarding usecase scaffolds.
- Some process labels in the UI that are not backed by a full lifecycle model.

Direct verdict:
- KEEP: task creation, goal creation, timeline review, completion fan-out, progression spine, settings permissions, monetization read surfaces.
- REDESIGN: routine and note process ownership, not-completed semantics, onboarding consolidation.
- MERGE: onboarding/tutorial/mission flow labels and intelligence summaries that overlap.
- REMOVE LATER: dormant onboarding usecase shells and any dead labels that never enter runtime.
- UNKNOWN: any route-adjacent behavior that needs device/runtime verification.
