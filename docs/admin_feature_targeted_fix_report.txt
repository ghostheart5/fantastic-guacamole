3. Old provider fallback behavior
- productInsightsProvider used try/catch and on any exception returned synthetic fallback insights directly.
- Failure state was not surfaced to UI/state consumers, so fallback could appear like healthy output.

4. New provider fallback/degraded behavior
- Added ProductInsightsState wrapper with fields:
  - insights
  - isFallback
  - warningMessage
- productInsightsProvider now returns ProductInsightsState.
- On normal path: returns insights with isFallback=false.
- On failure path: returns fallback insights with isFallback=true and warningMessage set to:
  "Advisor insights are running in fallback mode. Some source data could not be loaded."
- Provider now logs failure via dart:developer log (name: advisor_provider) without exposing raw details in UI.

5. How degraded/fallback state is surfaced in UI
- ProductAdvisorScreen now reads ProductInsightsState from productInsightsProvider.
- When isFallback is true, screen shows a compact warning tile above insights:
  "Advisor insights are running in fallback mode.\nSome source data could not be loaded."
- Insights still render below warning (screen remains usable).

6. Whether fallback output is still available
- Yes. Fallback insights are still returned and rendered when provider source data fails.

- Yes. Raw exception rendering was removed from ProductAdvisorScreen error branch.
