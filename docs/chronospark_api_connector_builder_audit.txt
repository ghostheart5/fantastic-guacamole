CHRONOSPARK APP API BUILDER / CONNECTOR BUILDER AUDIT

AUDIT MODE
- Read-only audit performed.
- No code edits, no schema edits, no SQL execution, no file renames/deletes.
- Scope is mobile app API/connectors/integrations only (not UX, not visual design, not DB redesign, not domain redesign).

1) AUDIT SCOPE
- In-scope: service layers, SDK usage, auth boundaries, connector reliability, payload mapping, external systems, reusable integration actions.
- Out-of-scope: screen aesthetics, product workflow critique, schema redesign, RLS rewrites.
- Evidence sources: app connector/service/provider files, auth layer, monetization layer, AI connector layer, Firebase bootstrap, Supabase gateways, local persistence connectors, env/config artifacts.

2) EXECUTIVE SUMMARY
- ChronoSpark uses a hybrid connector stack: Supabase (auth/data/storage/realtime), Firebase (core/analytics/crashlytics/messaging/remote config), Google Play billing (+ verification endpoint), and optional HTTPS AI proxy.
- Core connector architecture is modular and mostly resilient (retry wrappers, health checks, feature-gated behavior).
- Main risks are connector drift and configuration exposure risk (tracked env-like assets and generated config files containing sensitive values).
- Highest architecture gap: multiple parallel monetization connector paths with overlapping responsibilities.

3) INTENDED FLOW VS CONNECTOR REALITY
Intended flow:
Login -> Creator -> Create Task/Routine/Goal/Note -> Save local/remote -> Timeline reads scheduled records -> Completion updates -> Ascension/Future Vector/Smart Planner/SI Console -> Profile/Settings/Subscriptions.

Observed connector reality:
- Login/auth connectors are active and routed through Supabase.
- Creator/task/goal/routine persistence is primarily local repositories; cloud sync path exists through backup/sync connectors.
- Timeline/decision/AI/SI layers consume local/domain state and optional proxy connectors.
- Subscription/credits connectors are active and split across two monetization access layers.

4) CONNECTOR INVENTORY (SYSTEM MAP)
- Supabase connectors:
  - Auth: email/password, OAuth(Google), OTP, session refresh, password reset, sign-out, delete-account endpoint orchestration.
  - Data: user_daily_metrics and monetization tables via repositories/data sources.
  - Storage: chronospark-sync bucket for cloud backup JSON objects.
  - Realtime: stream on user_daily_metrics.
- Firebase connectors:
  - Core bootstrap, Analytics events, Crashlytics collection toggle, Messaging token/bootstrap, Remote Config feature flags.
- OAuth connectors:
  - Google OAuth active through Supabase signInWithOAuth(google).
  - GitHub OAuth configuration surface present; runtime sign-in path not implemented.
- Monetization connectors:
  - Google Play in-app purchase flow.
  - Receipt verification endpoint over HTTPS with bearer auth.
  - Supabase monetization tables and consume_monetization_credits RPC.
- AI connectors:
  - Optional HTTPS AI proxy endpoint.
  - Local SI engine fallback path.
- Local persistence connectors:
  - SecureStore, SharedPrefs, Hive (+ encrypted support), sensitive prefs wrapper.

5) AUTHENTICATION + OAUTH CONNECTOR AUDIT
Primary boundary:
- Auth gateway selects implementation by environment/intelligence flags:
  - AlwaysAuthenticatedAuthService (mock mode)
  - MockAuthService (mock login)
  - UnavailableAuthService (misconfigured/not ready)
  - AuthService (Supabase-backed production path)

Active auth operations:
- signInWithPassword, signUp, signInWithOAuth(google), signInWithOtp/verifyOTP, resetPasswordForEmail, updateUser(password), resend verification, refreshSession, signOut, account-delete endpoint flow.

Session/token handling:
- Access token obtained from Supabase currentSession when needed for secure endpoints.
- Auth state streams exposed to Riverpod and mapped to app-level User model.

Risk notes:
- Good: explicit auth unavailability behavior, exception mapping, throttled sign-in attempts.
- Risk: default mock credentials and permissive non-production toggles increase accidental misconfiguration risk if release governance fails.

6) GOOGLE SIGN-IN AUDIT
- Implemented through Supabase OAuth provider google with configurable redirect URL.
- UI and controller wiring present for Google sign-in entry points.
- No direct google_sign_in SDK connector observed in this layer; OAuth is mediated by Supabase.
- Verdict: integrated and active.

7) GITHUB SIGN-IN AUDIT
- GitHub redirect env/config surface exists.
- Domain model/usecase naming for GitHub exists.
- Runtime connector implementation for GitHub OAuth is effectively absent (stub use case, no active provider invocation path found in inspected auth service).
- Verdict: partially scaffolded, not operational as a full connector.

8) SUPABASE INITIALIZATION + HEALTH AUDIT
Initialization:
- SupabaseClientService initializes Supabase only when not in mock mode and credentials/config are valid.
- Includes timeout and retry logic.

Health checks:
- Provider verifies:
  - configured/initialized/authenticated state
  - DB reachability (user_daily_metrics select)
  - Storage reachability (chronospark-sync list)
  - Realtime token presence
- Permission-denied states are classified separately from connectivity failures.

Verdict:
- Strong health observability and graceful degradation.

9) SUPABASE CALL MATRIX (APP LAYER)
Auth API usage:
- auth.signInWithPassword(email,password): sign-in and re-auth for delete.
- auth.signUp(email,password,emailRedirectTo): account creation.
- auth.signInWithOAuth(google,redirectTo): Google OAuth entry.
- auth.signInWithOtp(phone), auth.verifyOTP(phone,token): phone OTP.
- auth.resetPasswordForEmail(email,redirectTo): password reset.
- auth.updateUser(UserAttributes): password update and bridge metadata sync.
- auth.resend(type:signup,email): email verification resend.
- auth.refreshSession(): session refresh.
- auth.signOut(): logout.

Data table usage:
- user_daily_metrics:
  - upsert on user_id,date with device_id and daily metrics payload.
  - select(eq user_id) for aggregation fetch.
  - health-check select().limit(1).
  - realtime stream(primary key user_id,date).
- Monetization tables (canonical + alias fallback paths):
  - monetization_subscription_plans / subscription_plans
  - monetization_subscription_statuses / subscriptions
  - monetization_credit_packages / ai_credit_packages
  - monetization_wallets / ai_credit_wallets
  - monetization_credit_transactions / ai_credit_transactions
  - monetization_purchases / ai_credit_purchases
  - monetization_entitlement_events / entitlement_events

RPC usage:
- consume_monetization_credits(params: credit_amount, reason, metadata)

Storage usage:
- Bucket chronospark-sync:
  - list(path: <uid>/backup) for health checks.
  - download/uploadBinary of JSON backup objects under uid-scoped paths.

User-id handling pattern:
- Most Supabase data operations gate on currentUser.id.
- Unauthenticated branches return safe defaults or explicit backend-unavailable errors.

10) FIREBASE CONNECTOR AUDIT
Active connectors:
- firebase_core initialization with platform options.
- firebase_analytics event logging (platform constrained + runtime checks).
- firebase_crashlytics enable/disable collection by env and platform.
- firebase_messaging permission/token/refresh/background/foreground handlers.
- firebase_remote_config refresh with env fallback snapshot.

Observations:
- Runtime checks prevent hard crashes when unsupported/not initialized.
- Firebase is leveraged mainly for telemetry/messaging/feature flags, while identity and app data are Supabase-centric.

11) SUBSCRIPTION + PAYMENT CONNECTOR AUDIT
Connectors observed:
- Google Play billing via in_app_purchase wrappers.
- Purchase verification over HTTPS endpoint with bearer token.
- Supabase monetization repositories for plans/status/wallet/events/transactions.

Strengths:
- Verification endpoint enforces HTTPS parsing and auth token requirement.
- Retry strategy for transient network/server responses.

Risks:
- Parallel monetization access patterns exist:
  - monetization_remote_data_source
  - feature-specific repositories
  - paywall repository variants (testing/platform-specific)
- This increases mapping and behavioral drift risk.

12) AI / SI CONNECTOR AUDIT
Active paths:
- ChatAgent attempts HTTPS AI proxy first when configured and prompt is non-empty.
- Uses minimized context/history payload and retries transient failures.
- Falls back to local SIAIService/engine when proxy is unavailable or invalid.

Security boundary:
- Proxy authorization uses Supabase access token when available (required in production path).

Risk profile:
- Good fallback safety and timeout handling.
- Output contract from proxy is loosely typed (message/reply); robust enough but should remain schema-validated if endpoint evolves.

13) ANALYTICS CONNECTOR AUDIT
- AppAnalytics gates by runtime intelligence flag.
- Logs locally + runtime diagnostics, then forwards events to FirebaseAnalytics if supported/initialized.
- Non-fatal error handling around missing plugins/platform exceptions.
- Verdict: resilient and non-blocking.

14) NOTIFICATION CONNECTOR AUDIT
- Local notification scheduling pipeline present (NotificationScheduler + orchestration service).
- Firebase Messaging token acquisition and refresh pipeline active.
- Bridge repository syncs FCM token into Supabase user metadata (rate-limited by dedupe interval).
- Verdict: practical hybrid connector design (local scheduling + cloud token identity sync).

15) LOCAL PERSISTENCE CONNECTOR AUDIT
- SecureStore abstraction (real backend vs in-memory mock).
- SharedPrefs service and sensitive prefs wrapper.
- Hive service with secure cipher management support.
- Local cleanup services for sign-out/account deletion/session hygiene.
- Verdict: broad local connector coverage with testability hooks.

16) CREATOR -> TIMELINE -> COMPLETION CONNECTOR PATH AUDIT
- Creator actions flow through providers and domain repositories.
- Task/goal/routine repositories are predominantly local persistence adapters.
- Timeline and SI/decision layers consume domain/provider state.
- Completion status side effects can feed analytics and optional completion-event tracking layer.
- Gap: remote transactional write path for creator artifacts is not unified with direct Supabase table CRUD; cloud sync is backup-style object sync rather than normalized remote CRUD in this layer.

17) PROFILE / SETTINGS / SUBSCRIPTION CONNECTOR PATH AUDIT
- Profile/settings operate through local stores and provider state.
- Subscription state is sourced through monetization repositories + billing verification flow.
- Settings contains operational hooks for account deletion and debug surfaces (non-release gated in relevant areas).
- Verdict: functionally connected, but monetization connector consolidation is needed.

18) ERROR HANDLING, RETRY, AND RESILIENCE AUDIT
Strong patterns observed:
- runWithRetry wrappers on sensitive network calls.
- Timeout limits on remote calls.
- Non-fatal logging and graceful fallbacks.
- Health providers and environment-readiness checks.

Weak points:
- Multiple connector implementations for similar concerns can produce inconsistent error semantics and fallback behavior.

21) GAP + RISK REGISTER (PRIORITIZED)
P0
- Secret/config exposure risk from tracked files and generated assets carrying env-like values.

P1
- Monetization connector duplication and alias fallback complexity increase drift risk.
- GitHub sign-in appears scaffolded but not fully implemented; may create false capability assumptions.

P2
- Creator-domain remote CRUD path not unified (backup-sync centric vs normalized API-centric writes).
- Mixed connector semantics (same domain data reachable through multiple layers) complicate long-term maintenance.

22) SAFE CONNECTOR ROADMAP (NO SCHEMA/RLS CHANGE)
Phase A (Security hardening, immediate)
- Enforce secret hygiene and artifact exclusion in release pipeline.
- Add static checks to fail CI if mock/paywall bypass flags are active in production builds.

Phase B (Connector normalization)
- Consolidate monetization connector entry points behind one canonical repository facade.
- Preserve alias fallback telemetry temporarily; then deprecate aliases by policy once migration confidence is high.

Phase C (Auth/OAuth completion)
- Either implement full GitHub OAuth runtime path or remove dormant scaffolding from release expectations.

Phase D (Operational contracts)
- Define strict request/response DTO contracts for AI proxy and verification endpoints.
- Standardize error codes and retry strategy wrappers across all network connectors.

Phase E (Flow alignment)
- Introduce a single explicit app-level connector contract for Creator->remote persistence (without changing DB design now), then map existing local/backup paths behind it.

23) FINAL VERDICT + SCORECARD
Overall verdict:
- ChronoSpark connector architecture is functional and reasonably resilient, with strong Supabase/Firebase integration primitives and safe fallback behavior.
- It is not yet fully normalized as a single API connector architecture because monetization and some auth/OAuth surfaces are fragmented/scaffolded.

Connector maturity score (audit-only estimate):
- Supabase integration: 8.5/10
- Firebase integration: 8.0/10
- Auth/OAuth boundary quality: 7.5/10
- Monetization connector cohesion: 6.5/10
- AI connector resilience: 7.5/10
- Secret/config operational safety: 5.5/10
- Overall API/Connector Builder readiness: 7.2/10

Immediate top 3 safe priorities:
1. Secret/config hygiene enforcement in CI and artifacts.
2. Monetization connector consolidation to one canonical integration surface.
3. Complete or explicitly retire GitHub OAuth path to eliminate integration ambiguity.
