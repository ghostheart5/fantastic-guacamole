CHRONOSPARK PROGRESSION WRITE MAP
Date: 2026-08-01
Scope: Places where XP, level, streak, and longest streak are modified across the progression/profile stack.

INTENDED CANONICAL FORMULA
- Intended canonical progression formula appears to be the ProgressionPolicy / UserProgress model:
  - levelFromXp(xp) = floor(sqrt(xp / 100)) + 1
  - xpForLevel(level) = (level - 1)^2 * 100
  - levelProgressFraction(xp) and xpToNextLevel(xp) derive from that same banded model
- Evidence for intent:
  - lib/domain/policies/progression_policy.dart defines the explicit level math and comments it as the level model.
  - lib/state/models/user_progress.dart uses ProgressionPolicy.xpForLevel(), xpToNextLevel(), and levelProgressFraction().
  - The Progression screen UI consumes UserProgress.
- Important caveat:
  - The actual write paths are not fully aligned with that intended formula.
  - ProfileController.addXP() uses a linear rollover rule.
  - ProgressionEntity.addXp() uses a cumulative threshold rule.
  - Several domain usecases update XP without recomputing derived level.

NOTES ON LONGEST STREAK
- Longest streak is only directly modified in lib/state/controllers/profile_controller.dart.
- It is updated in:
  - addXP(int amount)
  - incrementStreak()
  - setProgressionSnapshot({xp, level, streak})
- No other direct longestStreak write paths were found in the inspected progression stack.

CANONICALITY ASSESSMENT
- Most likely intended canonical formula: ProgressionPolicy / UserProgress banded model.
- Why that is the best-supported intent:
  - The Progression screen’s visual math uses UserProgress.
  - UserProgress derives progress from ProgressionPolicy.
  - ProgressionPolicy is the only place with an explicit documented leveling formula.
- Why it is not yet canonical in implementation:
  - ProfileController.addXP() uses a different formula.
  - ProfileEntity.addXp() uses yet another formula.
  - Domain usecases often mutate XP without recalculating level.
  - Repository bridging can persist whatever profile state last wrote, even if level is stale.

RISK SUMMARY
- XP can be incremented through multiple front doors, but level can be computed by different formulas depending on which layer handled the write.
- Streak and longest streak are much more localized, with ProfileController acting as the primary writer.
- The biggest correctness risk is XP-to-level drift, not streak drift.

RECOMMENDED SINGLE SOURCE OF TRUTH
- Use one progression formula everywhere XP changes.
- Recompute level from XP at the same boundary in every writer.
- Keep streak and longestStreak owned by ProfileController unless a dedicated progression domain service becomes the sole writer.
