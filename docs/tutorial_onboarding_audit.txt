ChronoSpark Onboarding + Tutorial Audit
Date: 2026-07-29
Scope: AUDIT ONLY (no code changes)

1. EXECUTIVE SUMMARY

ChronoSpark currently has multiple overlapping onboarding/tutorial systems, not a single source of truth.

Observed systems:
- Mission-based onboarding gate: lib/features/onboarding/ui/onboarding_screen.dart + lib/tutorial/mission/* + app-level mission lock in lib/app/navigation_shell.dart.
- Overlay-based tutorial engine: lib/tutorial/tutorial_controller.dart + lib/tutorial/tutorial_overlay.dart + assets/tutorials/*.json.
- Card/hint-based micro tutorial: lib/tutorial/widgets/micro_tutorial_card.dart + lib/tutorial/widgets/show_me_again_button.dart + lib/tutorial/tutorial_provider.dart.
- Screen-navigation-based gating: lib/app/router/app_router.dart redirect logic and initial location resolution.
- Legacy/unused onboarding state machine: lib/onboarding/controllers/onboarding_controller.dart + lib/onboarding/state/onboarding_state.dart.

Current onboarding style classification:
- slide-based: Minimal/legacy presentation shell only (slides list is empty; total pages set to 1).
- mission-based: Yes, strong and mandatory via mission lock + mission progression.
- overlay-based: Implemented but mostly dormant in current runtime flow.
- card/hint-based: Active (Creator micro tutorial card).
- screen-navigation-based: Active (router redirects and mission lock enforcement).
- mixed/conflicting: Yes.

Verdict: MERGE

3. FLOW MAP

3.1 Fresh install
- Start: main() -> AppBootstrapper run.
- Startup state: app_bootstrap loads prefs and canonical onboarding_state_v1, resolves OnboardingStatus.
- Route decision:
  - unknown -> /onboarding
  - incomplete + unauthenticated -> /onboarding
  - incomplete + authenticated -> /home (mission surfaces allowed)
- Flags/keys:
  - onboarding_complete / onboarding_content_version / onboarding_step_index
  - per-user variants *_<userId>
  - onboarding_state_v1 and onboarding_state_v1_<userId>
- Completion condition: not complete until mission finished and finalized in AppRoot.

3.2 First login
- Start: /login via AuthGate if onboarding complete and unauthenticated, or callback exceptions while onboarding incomplete.
- Next: router redirect sends authenticated user with complete onboarding to /home; incomplete onboarding may still route /onboarding, but special mission activation surfaces are allowed.
- Route calls: context.go in auth flows/router redirect.
- Flags: authenticatedGuardProvider, onboardingStatusProvider, profileCompleteGuardProvider.

3.3 Onboarding start
- Start screen: /onboarding (OnboardingScreen).
- Action: DEPLOY MISSION ZERO button -> _beginMissionZero().
- State writes:
  - onboarding complete false
  - onboarding content version set to TutorialContent.contentVersion
  - onboarding step index set 0
  - onboarding_state_v1 JSON persisted (complete:false)
  - provider states set onboardingComplete=false and OnboardingStatus.incomplete.
- Next screen: /home if authenticated, else /login.

3.4 Onboarding finish
- Not completed in onboarding_screen.dart.
- Mission complete path sets MissionState.finished=true when completion banner dismissed.
- AppRoot listener on missionStateProvider triggers _finalizeMissionZeroActivation().
- Writes on finalize:
  - onboarding_complete true
  - onboarding_content_version current
  - onboarding_step_index 0
  - onboarding_state_v1 JSON complete:true
  - providers set onboarding complete/complete status
- Next: context.go(RoutePaths.home).

3.5 Tutorial start
- Card tutorial start:
  - MicroTutorialCard init calls tutorialProgressProvider.startTutorial().
  - currently observed in Creator tutorial panel only.
- Overlay tutorial start:
  - TutorialController.start(tutorialId) exists but no runtime call found.

3.6 Tutorial reset
- API exists: tutorialProgressProvider.reset()/resetAll().
- Persistence behavior: resetToVersion(contentVersion) in tutorial_repository.
- UI trigger found: none in settings/main surfaces.

3.7 Tutorial replay
- API exists: tutorialProgressProvider.replayOnboarding().
- Behavior: sets onboarding_complete false + onboarding_content_version 0, then tutorial reset.
- UI trigger found: none.

3.8 Mission Zero start
- Trigger: onboarding DEPLOY MISSION ZERO.
- Mission state source: mission_repository.load() default MissionState.initial() (active createFirstGoal).
- App lock: NavigationShell _requiredActivationView() forces required view while onboarding incomplete and mission unfinished.

3.9 Mission Zero complete
- Step progression:
  1) reportGoalCreated -> complete createFirstGoal
  2) reportActionHubOpened -> complete openActionHub
  3) reportSmartCoachQuestionAsked -> complete askSmartPlannerQuestion
  4) reportTimelineOpened -> complete openTimeline and activate completion step
  5) MissionOverlay auto-dismisses completion banner in 3s (or manual dismiss) -> finished=true
  6) AppRoot detects finished and marks onboarding complete true

11. CONFLICTS AND DUPLICATES

Conflict A: Multiple onboarding/tutorial systems
- Mission progression, overlay tutorial engine, and micro tutorial cards all exist with different progression semantics.

Conflict B: Onboarding screen vs mission completion ownership
- onboarding_screen sets incomplete and launches mission.
- app_root completes onboarding later based on mission finished.
- completion is not tied to onboarding screen final action.

Conflict C: Overlay engine loaded but not truly started
- TutorialHost + assets loaded globally.
- No start(tutorialId) call observed, so overlay flow likely dormant.

Conflict D: Tutorial asset target mismatch
- home.json/tasks.json target IDs (goals.add_button, tasks.add_button, tasks.title_input) not found as registered TutorialTarget ids.

Conflict E: Vocabulary drift
- Smart Planner vs Smart Coach.
- Action Hub vs Creator.
- Soul Map semantics under Timeline labels.
- Creator Workspace vs Goals terminology overlap.

Conflict F: Mission requirements vs first-user workflow claim
- Mission currently requires goal creation, coach query, timeline open.
- It does not require task/action creation explicitly.
- Timeline completion is screen visit, not schedule proof.

Conflict G: Legacy onboarding system still in repo
- lib/onboarding/* state machine appears unused and overlaps conceptually with feature onboarding.
